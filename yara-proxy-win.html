Mitigation

📅 March 2026 🏷 Accenture Security ATHENA

Effective RustyRocket detection and mitigation require a combination of file, memory, and network detections. The following recommendations reduce RustyRocket risk across all known variants.

File & Memory Detection

  • Scan for Windows and Linux RustyRocket samples within your network using the YARA rules provided in this report. The All_RustyRocket rule covers both platforms simultaneously.

Network Detection

  • Monitor for unexpected TLS connections between hosts that do not regularly communicate with each other.
  • Alert on invalid TLS SNI values such as "server", "router", or "proxy" — RustyRocket uses these as C2 handshake markers.
  • Deploy JA4 and JA3 fingerprint alerts using the fingerprints in the Network Fingerprints section to flag potential RustyRocket TLS traffic at the network layer.
  • Monitor for increases in TLS traffic to unknown or newly-seen domain names, especially those with randomized subdomains matching RustyRocket's generation pattern.
  • Strip and inspect TLS where capable: look for WebSocket connections or TLS-within-TLS tunnelling inside ostensibly normal HTTPS sessions — a key RustyRocket evasion technique.
Priority action: The combination of invalid SNI values and the JA4 fingerprint (t13d041000_16476d049b0b_f568d6c2d1f6) provides the highest-confidence network-layer detection signal with minimal false-positive risk.
